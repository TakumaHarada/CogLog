# プロダクトとドメイン

## プロダクト

CogLog は、エアロバイクの運動履歴を記録し、減量を支える Flutter アプリケーションである。

- 記録の対象は、据え置き型のエアロバイクで行った運動である。
- 主機能は、エアロバイクの走行記録である。
- 利用者が支える目的は減量である。
- 画面の文言は日本語を優先し、英語も持つ。
- 対応するのは Android と iOS である。
- ヘルスコネクトおよび Apple ヘルスケアと連携する。

## ドメインの言葉

確定している言葉は次のとおり。表に無い振る舞いは実装しない。

| 言葉 | 意味 |
| --- | --- |
| エアロバイク | 運動履歴の発生源になる据え置き型の自転車 |
| 運動履歴 | エアロバイクで行った運動の記録 |
| 減量 | 運動履歴の記録によって支える目的 |
| メーターパネル | エアロバイクに付く、走行結果を表示する計器 |
| メーターパネル写真 | メーターパネルを写した写真。走行記録の入力元になる |
| 走行距離 | その走行で進んだ距離 |
| 運動時間 | その走行にかかった時間 |
| 平均速度 | その走行の平均の速さ |
| 消費カロリー | その走行で消費したカロリー |
| 読み取り | メーターパネル写真から走行距離、運動時間、平均速度、消費カロリーを取り出すこと |
| 読み取りエンジン | 読み取りに使う解析手段。VisionOCR、FoundationModel、ML Kit、Gemini Nano |
| 手打ち | 利用者が値を直接入力すること |
| 累積 | 現在までの走行距離、消費カロリー、運動時間の合計 |
| ヘルスサービス | ヘルスコネクトと Apple ヘルスケア |
| 体重 | ヘルスサービスから読み取る身体の指標 |
| 骨格筋率 | ヘルスサービスから読み取る身体の指標 |
| 体脂肪率 | ヘルスサービスから読み取る身体の指標 |

「走行記録」は主機能の名前である。運動履歴と同じ概念かは未確定のため、別の言葉としては置かない。

## 走行記録

1 件の走行記録は、次の 4 つを持つ。

- 走行距離
- 運動時間
- 平均速度
- 消費カロリー

値の入り方は 2 通りある。

- メーターパネルを撮影し、読み取りエンジンで解析する。
- 手打ちする。読み取りエンジンが使えないときと、読み取りミスを調整するときに使う。

どの端末でどの読み取りエンジンを使うかは未確定。

## 累積

利用者は、現在までの次の合計を見られる。

- 走行距離
- 消費カロリー
- 運動時間

合計する期間は未確定。

## ヘルスサービス

- 走行記録をヘルスサービスと連携できるようにする。CogLog から書き込む項目は未確定。
- ヘルスサービスから体重、骨格筋率、体脂肪率を読み取る。
- エアロバイクによる運動と、身体の指標の経過を比較できるようにする。比較の対象と期間は未確定。

## 未確定

この節の項目は、決まるまで実装しない。

1. 「走行記録」と「運動履歴」は同じ概念か。
2. 1 件の境界。写真 1 枚が 1 件か。記録が持つ日付は何か。
3. 読み取り結果と、手打ちで調整したあとの値を両方残すか。
4. 走行距離、運動時間、平均速度、消費カロリーの単位。4 つはすべて必須か。
5. 平均速度はメーターパネルの表示を正とするか、走行距離と運動時間から求めるか。
6. 累積の期間。記録を直したあとに合計をどう更新するか。
7. ヘルスサービスへ CogLog が書くもの。体重、骨格筋率、体脂肪率を CogLog で手入力するか。
8. 運動と経過の比較が、何と何をどの期間で並べるか。

新しい概念、属性、画面、計算を実装する前に、この文書へ定義を追加する。この文書に無いドメインの振る舞いは実装しない。
